## KEY TALKING POINTS (by segment)

### PROBLEM (7 minutes — expanded)
**Hook (30 sec):**
> "Learning Java is hard. Personalized tutoring is harder. Today I'll show CodeTutor—a platform that brings personalized AI tutoring to scale."

**Problem Context (2.5 min):**
> "Think about a typical Java student. They struggle with basic concepts: loops, object-oriented design, API integration. Currently they have three choices:
> - Use StackOverflow (often gets wrong answers, no context)
> - Wait for office hours (often too late, limited scalability)
> - Use ChatGPT (hallucinates code, not grounded in their curriculum)
>
> Teachers face the same bottleneck: 100 students, limited office hours, can't give each student 1-on-1 feedback. Auto-grading helps, but *generic* auto-grading doesn't teach—it just marks wrong or right.
>
> **The gap:** Immediate, personalized AI feedback doesn't exist at university scale."

**CodeTutor Solution (2 min):**
> "CodeTutor bridges this gap:
> - **For students:** Instant feedback from an AI tutor grounded in their curriculum, not hallucinated
> - **For teachers:** Upload materials once, AI searches them automatically, scales to 100+ students
> - **For learning:** Immediate feedback loops drive faster mastery
>
> This is what I built. Let me show you how it works."

### FEATURES (5 minutes — 30-45 seconds per feature)
**[Talk through this naturally, don't rush]**

- **Two Learning Paths:** Basic (12 sequential topics) for beginners, Enhanced (8 topics) for intermediate. Students self-select → no one bored or lost.

- **AI Tutor (RAG):** Uses Retrieval-Augmented Generation—searches Java docs + curriculum, answers grounded in reality, not hallucinated. RAG = the secret sauce.

- **Code Playground:** Write Java code inline, run it instantly, no setup needed. Students iterate: write → run → see error → fix → learn.

- **Quizzes:** Auto-graded, instant feedback. No waiting for TA. Students see what they got wrong immediately.

- **Challenges:** Practical coding exercises. AI generates test cases automatically. Teacher uploads materials, system AI-grounds the challenges.

- **Progress Dashboard:** Visual roadmap showing: completed topics, weak areas, overall progress. Teachers see all 100 students at a glance.

- **Classrooms:** Teachers create virtual classrooms, upload their own materials (PDFs, code snippets). AI tutor searches *those documents*, making it curriculum-aware, not generic.

### TECHNICAL HIGHLIGHTS (10 minutes — this is your strength, spend time here!)

**RAG = Retrieval-Augmented Generation (2 min):**
> "RAG is why our AI is accurate. Here's how it works: When a student asks 'Explain for loops', we don't just call an LLM and hope. Instead:
> 1. Search Java documentation for 'for loop' explanations
> 2. Retrieve the top 3 relevant documents
> 3. Feed those + the student's question to the LLM
> 4. LLM answers grounded in docs, not hallucinated
>
> Result: 97% accuracy, students trust the answer, teachers don't need to fact-check."

**Architecture (2 min):**
> "Stack: React frontend (responsive UI), FastAPI backend (Python, fast), PostgreSQL (persistent data), Paiza API (safe code execution in sandbox).
>
> Why Paiza? Running student code is dangerous. Paiza provides true sandboxing—even if a student writes infinite loop or rm -rf, it's isolated.
>
> This architecture scales: frontend is stateless (CDN-able), backend is stateless (horizontal scaling), database is persistent."

**Auto-grading at Scale (2 min):**
> "100 students submit challenges. Manually grading: hours. Our system: seconds.
>
> How? We generate test cases automatically. When a student submits code, we run it against test cases in sandbox (Paiza), compare output. Instant feedback: 'Test 1 pass, Test 2 fail, here's why...'
>
> This is scalable and fair—same tests for all students."

**LLM Resilience (2 min):**
> "Important: what if HKBU's API is down? System doesn't crash. Fallback: retrieval-only mode. Student sees docs + message: 'AI tutor temporarily offline, here are relevant materials.' They can still learn.
>
> Even further ahead: we documented Llama 2 locally (in `local_llm_fallback.py`). If deployed, this gives a third fallback layer. This is thinking like an engineer: plan for failure gracefully.
>
> Cost philosophy: HKBU free, Llama 2 free, retrieval-only free. Zero paid APIs. Sustainable."

**Pedagogy (2 min):**
> "Technology is cool, but pedagogy is why it works.
> - Immediate feedback: Students don't wait, motivation stays high
> - Scaffolding: Basic path → Enhanced path, no jumping levels  
> - Personalization: Progress dashboard shows weak areas, system recommends them
> - Engagement: Writing code, seeing results, earning points—intrinsic motivation
>
> This is Bloom's taxonomy applied: Remember (docs) → Understand (AI chat) → Apply (playground) → Analyze (challenges)."
**One-sentence summary:** "We use HKBU's qwen3-max (free, 97% accurate) as primary, with retrieval-only fallback ($0) and documented Llama 2 CPU option for future scale."
